# Internal literal-formatting RTF conversion

QUILS-110 is a default-disabled grammar gate. QUILS-124 adds [guarded sender intake](document-conversion.md#guarded-static-office-intake), requiring `Documents__EnableOfficeUploads=true`, `OfficeConversion__RtfEnabled=true` and a usable isolated HTTP converter. The original RTF and exact normalized PDF are published separately; the literal DOCX transport hash remains independent provenance. No sandbox source kind or hosted activation is added.

This reader tokenizes a complete bounded `rtf1` group. It requires ANSI; raw or hex non-ASCII bytes additionally require an explicit Windows-1252 declaration, independent of the machine's locale. Signed BMP Unicode escapes have scoped `uc` fallback counts; only literal/escaped/hex fallback characters are accepted. Surrogate escapes and other codepages fail. It preserves ordinary escaped braces/backslash, literals, paragraphs, tabs, line/page breaks, scoped bold/italic/underline, 8–24 point type, foreground RGB colors, a finite font table and simple root paragraph alignment. Unspecified fonts use the documented Liberation Sans conversion default. Fixed Letter paper and one-inch margins are the supported print profile.

The parser rejects unknown controls and destinations, including starred destinations. It never strips a destination and continues. Fields/instructions, object/OLE, pictures/metafiles/binary data, HTML/XML/file data, hidden text, stylesheets, metadata destinations, tables, lists, sections and unsupported layout fail closed. A balanced brace count, keyword blacklist or RTF suffix is insufficient. Unsupported Word/WordPad documents must be exported to PDF.

Before allocation or converter work, it bounds the original to one MiB and configured input limits, nesting to 32, groups/runs to 10,000, tokens to 150,000, text to 50,000 characters, paragraphs to 1,000, font/color tables to 32, numeric parameters and explicit pages to the configured page limit. Header placement, table uniqueness, exact numeric syntax, font charset, fallback accounting and final group/end-of-input are validated. Ambiguous, trailing or truncated payloads are rejected with a safe message.

Accepted semantics are serialized as literal XML in a new owned minimal DOCX. The existing DOCX content gate validates that package independently. The original RTF remains separate and exact; its SHA-256 is distinct from the derived DOCX hash and normalized PDF hash. A fixed enum selects the DOCX filename/media for isolated HTTP conversion, and the derived source hash is checked before returning a PDF with bounded Letter geometry/pages. Raw RTF is never submitted to format sniffing. Font substitution and layout require explicit review of the exact PDF before sender preparation continues.

Local evidence includes a real pinned-service two-page conversion inspected after rendering. It covers scoped formatting and restoration, font/color, CP1252 and Unicode, escaped text, tabs/line/page breaks, literal URL/formula-looking content and a harmless literal backslash keyword. Adversarial grammar/codepage/fallback/destination/expansion and output/transport cases pass alongside DOCX/PPTX/XLSX/ODT regressions. No new dependency, cloud operation or provider call is involved.

[Microsoft's RTF text interpretation guidance](https://learn.microsoft.com/en-us/openspecs/exchange_server_protocols/ms-oxrtfex/205e1abf-b794-4fd0-b1e4-5210882233ab) explains why decoding depends on control tokens, fonts and codepages. QuillSign's narrower accepted grammar and reject-on-unknown behavior are engineering choices, not a claim of full RTF conformance.
