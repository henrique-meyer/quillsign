# Signer PDF copy rendering

QUILS-34 provides a bounded internal `SignerPdfRenderer` for the later Finish/current-copy workflow. It has no HTTP endpoint, database/storage writes, signing-state transition, email or cryptographic seal. Renderer output alone does not complete signing.

The caller supplies exact hash-pinned PDF bytes/page metadata and a typed server snapshot: envelope/signer IDs, signer-record full name, a server Finish instant, current adoption and canonical assets, and owned field values/revisions/bindings. The future authorized Finish transaction must construct this snapshot from locked current records, validate consent/session/sequential eligibility, and recheck revisions/state before publishing the copy and audit evidence. The renderer does not authorize a client request or look up current database revisions.

Input PDF bytes are copied and independently hashed, validated through the upload policy, and compared against actual crop/rotation/UserUnit geometry. Source, field revision/hash arrays and mark bytes are defensively copied. Source bytes and persisted records remain unchanged. Shared bounded PDFsharp work uses the same process gate as sender rendering. No new native runtime dependency is introduced; PDFsharp remains MIT 6.2.4.

Only unique fields owned by the specified envelope/signer are accepted. Every field has an eight-byte revision and valid supported type/page/normalized bounds. Required fields must be explicitly saved by the signer before the Finish instant, except Date Signed. Optional cleared/blank text fields remain blank. Checked and unchecked are distinct saved checkbox responses. Generic calendar values require valid invariant `YYYY-MM-DD` dates. Partial, stale, unassigned or foreign state fails closed.

Signature/initials fields must name the current adoption, exact server asset object reference and matching image SHA-256. The supplied pair must match the supported normalization version, exact hashes and byte-for-byte canonical output of the strict PNG normalizer. Replaced marks, missing assets, metadata-bearing/noncanonical images and incomplete bindings cannot render. Marks retain transparency and aspect ratio, are centered inside the field, and must fit at a readable physical size. No caller-supplied arbitrary image/reference is accepted as an applied mark.

Full Name requires an explicit saved application matching the canonical signer-record name and is rendered from that record. Date Signed accepts no saved override/fill metadata and is derived from the supplied server Finish instant's **UTC calendar date**. That instant must be chosen and validated by the eventual Finish workflow; it is not exposed as client input. Text uses the existing pinned Liberation Sans font, supported Unicode/NFC/LF handling, explicit line breaks and adaptive 8–12-point fitting. Unsupported glyphs/scripts, controls or overflow reject the candidate instead of dropping characters, clipping text or stretching marks.

The output owns new PDF bytes, their SHA-256, exact source hash, envelope/signer/adoption IDs, UTC Finish instant, renderer version and a SHA-256 binding over the canonical rendering recipe. The binding includes field revisions/positions/values/fill metadata, current asset hashes, source hash and server-derived name/date context. Field ordering is deterministic. This is provenance for a later private audit record, not an independent authenticity proof or a seal.

Sequential processing must use the previous completed **current copy** as the next renderer's exact source. That retains sender-prefill and earlier signer contents without reapplying them. The original sender-frozen PDF remains immutable; the later workflow must version current-copy references/hashes and bind each next signer's invitation/consent/review to the correct copy. V1 seals only once after all signers complete. Already cryptographically signed, encrypted, malformed or XFA input is rejected.

Pure tests cover all types, UTC date/name derivation, Unicode/multiline values, optional/required entries, exact evidence/hashes, partial/stale/foreign state, limits, sequential preservation and mixed renderer concurrency. The existing field geometry harness now exercises the production signer renderer on nine letter/A4/landscape/crop/rotation/UserUnit cases, checks pixels/text/page metadata with independent rendering/parsing, and writes synthetic ignored PDF/PNG evidence. Run `pwsh -File scripts/dev/Test-PdfFieldSpike.ps1`; the existing harness Dockerfile provides the same Linux checks. Its native rendering dependencies remain development-only.
