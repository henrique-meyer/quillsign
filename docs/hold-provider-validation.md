# Isolated preservation provider validation

QUILS-155 verified the external immutable-witness provider prerequisite and completed the delayed synthetic-fixture cleanup. The experiment did not deploy production holds, select legal/operator policies or establish hosted release readiness. The owner approved a finite USD1 usage allowance and necessary bounded diagnosed repairs under the existing cost policy; every failed phase and uncertain intent remains accounted for.

The standalone `infra/hold-provider-pilot.bicep` template creates only a new private version-immutability-capable container and an existing user's temporary Storage Blob Data Owner assignment scoped to it. It is not included in normal hosting deployment. Actual deployment parameters, identities, raw receipts and private runner artifacts remain outside Git. The account, hosted application, existing containers, SQL, identities and protection/recovery policies were unchanged.

The guarded runner recorded request, attempted-write, version and byte consumption before possible provider operations. It used only its synthetic namespace and exact returned VersionIds; the production archive writer was not pointed at hosted final records. Native checks passed for exact historical version/ETag/length/hash/protection readback; locked deletion, shortening and policy-deletion refusal followed by unchanged protection readback; stale ETag and conditional-create refusal; independent legal holds and exact separate releases; unmatched intent/lost acknowledgement; actual local SQL backup restore/fresh-process quarantine; and complete namespace/fork detection. Local transport regressions support these checks but are not Azure evidence.

Earlier failures were retained and corrected within the original aggregate limits, without refunding attempts or changing original protection clocks. The complete external namespace was reconciled against authenticated disposable local SQL. Missing/conflicting witnesses, rolled-back SQL, unmatched intents, unknown provider outcomes and independently blocking holds denied destructive authority. Existing inherited account access was not removed or represented as isolation from other principals.

After the repository split, an additive cleanup-only package narrowly resolved the same existing execution under its moved private root. Its reviewed source/script/binary pins preserved the original finalization artifacts, approvals and full ledger. A warning-free build, 54 original local SQL/mock regressions, 20 relocation checks and 33 script/path/evidence checks passed before the scheduled execution. The repair itself made no provider call, replayed no window, widened no permission and created no replacement fixture.

The delayed cleanup then ran once after the latest recorded locked write-intent expiry plus one hour. It API-deleted all nine exact retained version selectors and performed five conditional root demotions matching original receipts, using exact version/ETag/bytes/protection checks and historical re-read. Empty-container absence and removal of the exact temporary assignment were verified natively; the owned child and independent watchdog exited. Only recorded disposable legal holds were cleared, and existing seven-day soft deletion was unchanged. The one-off cleanup automation was removed after terminal acceptance. API deletion is not a claim of physical erasure.

Final cumulative accounting is 498 ledger events, 207 data requests, 66 control invocations, 10 attempted writes, nine original retained-version receipts, 2,275 consumed bytes and one synthetic record. The original 362-event byte prefix and all failed phases remain intact. The original USD1 usage allowance (not a billing cap) was unchanged. Counted usage stayed within 1,000 data requests including a 300-request cleanup reserve, 32 attempted writes, 10MiB, the three-record maximum and explicitly amended 80-call control limit. No additional provider or cleanup invocation is needed. Application lifecycle and private operator source acceptance are separate from this provider experiment; no production activation follows from these results.
