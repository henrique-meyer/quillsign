# Exact signer review, Finish and confirmation

After saving their fields, a consented signer opens `/sign/{publicId}/review`. Loading this page reads saved state; it does not prepare a candidate, apply fields or sign. **Prepare exact review PDF** is an explicit antiforgery-protected POST. Required entries and current adoption must be valid. The immutable candidate includes the current verified source, owned saved fields and prospective server UTC Date Signed, with the existing ten-minute/session/envelope/midnight expiry bounds.

The review page offers that exact candidate through PDF.js, a separate PDF tab or a download. Candidate reads verify the full bounded bytes, hash and current snapshot before returning a PDF. There is no fallback to the original document. The saved-entry summary retains corrective field/capture links. Replacing marks, changing saved fields, expiry or a new UTC date requires explicit review preparation again.

Protected candidate and PDF-access proofs use bounded HttpOnly, SameSite=Strict cookies scoped to this request's signer path. Production cookies require HTTPS. Proofs stay out of URLs, HTML hidden fields and JSON bodies. Access evidence binds the original cookie receipt, candidate ID, exact PDF hash, complete isolated signer identity/session nonce and expiry. Reading a candidate creates a newly protected return receipt, so access evidence deliberately hashes the original request cookie rather than that regenerated value.

**Finish** requires both affirmative review and intent statements, the canonical server statement/version, a reported preview/download access method and the matching protected PDF-access proof. Access evidence means the server prepared the verified PDF for a response. The signer's statements report their own access and review; they are not proof the person read it. The existing acceptance backend rechecks current state, chooses actual server time, records immutable acceptance evidence, freezes fields and queues checkpoint work atomically.

Accepted HTML requests redirect to the clean `/sign/{publicId}/confirmed` URL, with a once-only notice. JSON requests receive confirmation metadata in the response body. The confirmation accurately distinguishes accepted/pending processing from a published signing copy. It offers manual refresh without recurring SQL polling. After publication, download uses the narrow own-checkpoint read contract and returns the exact accepted review bytes. Later signers do not replace this signer's owned copy. It does not claim final envelope completion or a final seal.

The private review proof remains in the browser only within the original session lifetime so a lost Finish response can recover an already durable acceptance. This does not extend the review deadline for a new Finish. An accepted proof may confirm/download after review expiry while the original session and envelope remain live. Voiding, envelope expiry or session expiry still denies access. Visiting editable signer routes with a valid accepted proof redirects to confirmation; accepted authority never restores edits.

Invalid/foreign/expired proofs fail closed. Recoverable errors do not claim that Finish succeeded or failed merely because its response was lost. Reload checks accepted state before retrying. A current verified candidate can redisplay submitted confirmations after a rolled-back failure; an unverifiable candidate is withheld until recovery. Repreparation clears prior access evidence and requires opening the PDF again.

Review/confirmation requests share the bounded signer interaction rate limit, use no-store/no-referrer headers and retain the existing isolated authentication, request-size and CSRF protections. Public Send, final sealing/certificates/completion delivery and actual operator disclosure policies remain separate work.
