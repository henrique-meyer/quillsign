# Static PPTX conversion component

This internal component is disabled by default. It adds no PPTX upload choice, persistence workflow, conversion work producer or hosted enablement. The public sender must continue to use PDF, configured DOCX, supported images, or separately enabled UTF-8 text. Public Office intake requires a later story and browser validation.

`PptxPackageValidation` accepts an owned conservative PresentationML profile: finite ordinary slides, static text and shapes, supported layouts/masters/themes, bounded drawing properties and content-verified internal PNG/JPEG images. Original bytes and SHA-256 are immutable after validation; independent streams and returned hashes cannot mutate the accepted source. Every non-relationship part must be reachable from the package root through an allowed internal relationship, with family-consistent type, root and target. Slide references are unique, the slide count fits the PDF page limit, and the declared slide dimensions are bounded.

It rejects macro/encrypted/signed packages, OLE, embedded packages/workbooks, ActiveX, actions/hyperlinks/external resources, media, fields, notes, hidden slides/shapes, unreviewed extensions, opaque binary printer settings, unknown parts/namespaces/attributes and malformed or inconsistent relationships. General PowerPoint templates can contain these structures even when the visible slides look simple. Those files must be exported to PDF; the application does not silently strip unknown content or pass it through to the importer. This is a documented subset rather than universal PowerPoint compatibility.

The common `BoundedOfficePackage` keeps the prior DOCX ZIP profile: matching local/central headers, exact CRCs, no ZIP64/encryption/aliases/links/alternate names/unlisted payloads, canonical names, finite decompression and no extraction. Each expanded part is at most16 MiB, all parts total64 MiB, with at most2,048 entries. XML is at most8 MiB per part and64 levels; PPTX additionally stops at250,000 aggregate elements during the streaming pass before constructing XML trees. Literal text totals at most 1 million characters, shapes at most 20,000 and relationships at most 4,096. Raster images reuse the existing strict header/expansion/profile gate, at most 12 million pixels each and 48 million pixels in aggregate. Shape positions/sizes, font sizes and shadow work have independent finite limits. Unsupported input fails before conversion with a generic message containing no uploaded content.

`StaticOfficeConverter` requires `OfficeConversion__PptxEnabled=true` (default false) plus a configured isolated HTTP converter. It accepts only the gate-created `ValidatedOfficeSource`, selects a fixed `document.pptx` name and verified MIME from the closed source-kind enum, and reuses the existing bounded HTTP/PDF normalization contract. It preserves exact original and normalized PDF hashes and checks that every output page matches the accepted slide count and landscape/portrait dimensions. It sends no user-controlled path, URL, callback or command. Cancellation, no redirects/proxy/retries/provider-body logging, safe errors and output/page limits remain unchanged.

The existing sandbox transport remains DOCX-only and rejects native PPTX without provisioning or fallback. Its fixed input path, commands and actual-source hash contract are unchanged. Native PPTX sandbox support and any hosted activation require separate implementation and owner-approved validation; this component consumes no existing Azure conversion budget.

Local evidence: the real pinned no-egress Gotenberg service converted a minimal two-slide presentation and a second two-slide presentation with an internal raster image, layout/master cycle and theme. All four 960 by 540 point pages were rendered and inspected, including text position, colors and image placement. Exact source/PDF hashes, geometry and text were verified. Adversarial gate/transport cases and all existing DOCX/text package regressions pass; source cleanup/provisioning and sender persistence are not claimed for PPTX. The converter has no default route and direct external DNS/IP connections fail. These are local checks only.
