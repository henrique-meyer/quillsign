# Bounded complete MIME preparation

`PreparedRawMime` prepares an artifact for the separately gated operator pilot. It is not registered with dependency injection or called by dispatch, pilot admission or either transport. Preparation has no database, storage, provider, credential or network dependency. Public email remains disabled; this utility grants no permission to send.

Call `PreparedRawMime.PrepareAsync(outgoingEmail, fromEmail, fromName, cancellationToken)` with the ordinary `OutgoingEmail` contract. The utility normalizes the single From/To addresses, validates bounded Unicode content, snapshots the mutable attachment list and copies the already-owned PDF attachment bytes before encoding. It keeps the ordinary maximum of two safe, distinct PDF filenames. Sender display names are at most 256 characters, subjects retain the existing 998-character limit, and combined text/HTML UTF-8 input is at most one MiB. Oversized inputs fail before MIME construction.

The existing pinned MimeKit constructs the full message: From, To, Subject, UTC Date, a fresh fixed-width GUID Message-ID under the reserved `quillsign.invalid` domain, MIME headers, optional `X-QuillSign-Envelope`, both text/HTML alternatives and any attachments. Non-ASCII headers use ordinary MIME encoding; text and attachment parts use Base64 with CRLF line endings. This does not require SMTPUTF8 or 8BITMIME. No user-supplied MIME header collection or raw MIME injection is accepted.

A fixed-capacity one-MiB output stream checks every write before copying it. The cap applies to **all actual serialized MIME bytes**, including headers, boundaries, transfer encoding, line wrapping, filenames and the final newline. Overflow aborts preparation without returning a partial artifact. Coarse attachment estimates are not accepted as evidence of the final size, and attachments are never omitted or replaced with links here. Temporary output and attachment copies are cleared after use. MimeKit's ordinary managed intermediate content is bounded by the input limits; this is not a promise to erase every managed string or allocation.

The result retains the exact serialized bytes, their `ByteCount` and SHA-256, normalized `Sender`/`Recipient`, `EnvelopeId` and submitted `MessageId`. Hash reads return copies. Every `OpenRead()` starts at zero, supports independent reads and seeking, rejects writes and cannot expose the private backing array. Reading again never regenerates dates, IDs, boundaries or encoding. These immutable objects retain their content for their managed lifetime, like the existing attachment contract; callers should keep that lifetime short and never log MIME content or private metadata.

The hash describes the artifact the later transport submits. It does not attest to the final mailbox bytes: a provider can rewrite headers. The one-MiB cap is on complete MIME, not HTTP/SDK request encoding, provider response size, network billing or delivered-mail behavior. Later ledger and raw-send slices must consume the same artifact without reconstruction, enforce exact run/recipient/expiry scope and reserve nonrefunded budgets before credential or provider access. None of those gates is implemented or bypassed by this utility.

Focused local tests parse complete messages with the pinned MimeKit and verify Unicode headers/bodies/filenames, both empty and nonempty alternatives, exact attachment bytes, envelope metadata, seven-bit CRLF serialization, actual byte count/hash, independent non-writable reads, mutable-list snapshots, cancellation, hostile header/body content and bounded inputs. A full message exactly one MiB is accepted; one additional header byte is rejected. Base64-inflated messages are rejected even when decoded data fits. No real message or provider request is needed for these checks.
