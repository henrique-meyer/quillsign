# Restricted pilot feedback simulator

QUILS-137 adds an optional backend for the three fixed [Amazon SES mailbox simulator](https://docs.aws.amazon.com/ses/latest/dg/send-an-email-from-console.html) cases: success, hard bounce and complaint. These public protocol fixtures contain no operator contacts. The source does not activate sending or install a route.

`EmailPilotSimulatorAdmission.RequestAsync(capability, kind, cancellationToken)` checks the configured operator capability before resolving SQL or keys. The existing protected run and exclusive run lock admit one deterministic Work/Outbox pair for each kind. Both rows retain a null envelope and distinct protected JSON payloads bound to the run, work identifier and kind. The hint is persisted before commit; publication follows commit. A repeated request authenticates the same persisted rows and returns their existing identity, including after a lost commit or publication acknowledgement. Admission creates no document, signer, token or session and consumes no provider budget.

`EmailPilotSimulatorAuthority` independently verifies the live configured manifest, operator hash, protected source, exact fixed target, actual current owned Email lease, status, deadlines and suppression. Its server-created scope is separate from document/application authority. It cannot authorize an arbitrary address or an application message. Known simulator work routes through its dedicated optional handler before the document-only pilot decision; absence of that handler never grants ordinary delivery.

The delivery handler commits normal submission intent for that exact lease and attempt. `EmailPilotSimulatorSender` prepares one immutable MIME artifact containing only fixed synthetic text. Before resolving the raw transport or credentials, it reserves a Simulator attempt with Simulator role, no subject envelope, the complete encoded size and exact hash. Existing nonrefunded limits of ten simulator attempts, one MiB per message, thirty MiB aggregate mail and the original sixty-minute run still apply. It then rechecks source, lease, configuration, intent, suppression and deadline. The checked raw SES adapter consumes those exact bytes with no SDK retries or redirect replay.

A consumed or uncertain reservation never grants another invocation. Unknown provider, factory or receipt-write failures preserve intent; ordinary WorkStore recovery marks ambiguous work without resending. Only a definite provider rejection clears intent, and a later owned attempt consumes another reservation. A successful submission stores the ordinary provider/message receipt. Existing signed feedback processing can correlate that receipt and apply normal bounce/complaint status and suppression; this backend does not fabricate feedback or bypass suppression.

Private operator CSRF/rate limits, routes, complete runtime composition and approved hosted validation belong to the later pilot integration. Default public email and demo reminders remain disabled. Local SQL and fake raw transport validation are source checks, not evidence that a real SES event or hosted signing flow succeeded.
