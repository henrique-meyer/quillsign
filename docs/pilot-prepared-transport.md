# Restricted pilot prepared transport

QUILS-130 provides an unregistered source component for the restricted operator pilot. It does not enable public email or process work automatically. `EmailPilotSender` is separate from `IEmailSender`; ordinary sender behavior remains unchanged.

After committing its normal typed submission intent, a supported handler may call `EmailPilotSender.SendAsync(WorkLease, OutgoingEmail, CancellationToken)`. The component derives authority from the protected run and original admission, exact current lease and approved mailbox role. It separately requires the committed queued intent for that same outbox, envelope, recipient and attempt, with no recorded provider receipt, before reservation and at the final boundary. It rejects unrelated work, changed contacts, wrong envelopes and unsupported mail kinds through the QUILS-128 verifier. Lookup mail without an envelope needs a separate supported authority; this component rejects it.

The sender checks suppression and serializes one immutable [prepared MIME artifact](bounded-raw-mime.md). It records its exact SHA-256 and complete encoded byte count, at most one MiB, in the existing nonrefunded ledger. Reservation and operation identifiers are deterministic for the work attempt; the reservation identifier also prevents changed bytes or recipient roles reopening that attempt. A previous reservation is consumed status evidence, never reusable permission. A lost commit acknowledgement cannot reach the provider, and retrying the same attempt cannot submit again.

Authority, configuration, original expiry and suppression are checked again after the isolated reservation commits. Only then can the factory receive immutable SES settings and construct its provider or resolve credentials. The original lease/run deadline bounds cancellation; authority is checked once more after factory construction. Errors do not refund or retry. Absent, stale or consumed authority throws `EmailPilotTransportRefusedException`. A consumed/conflicting reservation proves only that the current invocation cannot send; a prior or concurrent invocation may already have called the provider. Preserve the original submission intent on this custom exception rather than translate it to a known-unsent exception, clear intent or create a new attempt. Unknown reservation/commit outcomes and provider exceptions likewise propagate for the typed handler's existing ambiguous-submission disposition.

`IPreparedEmailTransport` accepts the captured artifact without regenerating headers, boundaries or message identifiers. `SesPreparedEmailTransport` sends SES v2 Raw content with one explicit destination, no CC/BCC, the configured configuration set and the same stored bytes. It requires a matching regional HTTPS SDK client with `MaxErrorRetry=0`, `AllowAutoRedirect=false` and no custom service URL. The pinned SDK defaults automatic redirects to true, so the existing ordinary client must not be reused unchanged; configure the pilot client explicitly. Its factory stays lazy; constructing the component alone must not resolve AWS credentials. SMTP is outside this restricted hosted pilot.

The accounting operation needs a clean, isolated database context without another transaction or pending changes. Do not call the sender inside the typed handler's intent transaction or while holding conflicting envelope locks. Do not retain an earlier authority snapshot across legitimate payload/token binding. Later orchestration must reacquire authority after that commit, preserve existing provider intent/receipt handling and ensure expired enrolled work cannot fall back to ordinary delivery.

This slice adds no startup registration, operator route, dispatch integration, lookup/session authority, timestamp requests, hosted settings, credentials or cloud resources. Those remain dependent integration and checked rollout work. Tests use local SQL and synthetic captured provider requests; they do not establish hosted mailbox delivery.
